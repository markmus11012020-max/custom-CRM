РУКОВОДСТВО АДМИНИСТРАТОРА CUSTOM-CRM

1. ПЕРВЫЙ ЗАПУСК

Проверьте .env:
  SECRET_KEY
  ADMIN_EMAIL
  ADMIN_PASSWORD
  DATABASE_URL

Запустите start.bat.
После healthcheck откройте http://127.0.0.1:8000
Войдите администратором и смените пароль в профиле.

2. ПОЛЬЗОВАТЕЛИ И РОЛИ

Администратор:
  полный доступ, пользователи, проекты, настройки, все данные.

Менеджер:
  создание и редактирование клиентов, сделок, задач, платежей, склада
  и транзакций в проектах, где он участник.

Наблюдатель:
  только чтение данных проектов, где он участник.

Создание пользователя:
  Администрирование -> Пользователи -> Новый пользователь.
После создания добавьте пользователя в проект:
  Администрирование -> Проекты -> Изменить -> Участники.

3. ПРОЕКТЫ

Каждый проект изолирует клиентов, сделки, задачи, платежи, склад и учёт.
Активный проект переключается в левом меню.
Администратор видит все проекты.
Менеджер и наблюдатель видят только проекты, где они участники.

4. GOOGLE

Настройка описана в docs/google-setup.txt.
Проверка статуса и создание папки:
  Администрирование -> Настройки.
OAuth2-вход выполняется командой:
  python -m app.google.oauth_user --login

5. ROBOKASSA

В .env задайте MerchantLogin, Password1, Password2.
Для теста установите ROBOKASSA_TEST_MODE=true.
ResultURL должен быть доступен из интернета.
Если реквизиты не заданы, используйте ручную отметку оплаты.

6. УВЕДОМЛЕНИЯ

SMTP и Telegram настраиваются в .env.
В профиле пользователя укажите email, Telegram chat_id и включите каналы.
Тестовая отправка:
  Администрирование -> Настройки -> Тест email / Тест Telegram.
Если канал не настроен, уведомление получает статус skipped.

7. ОТЧЁТЫ И РАСПИСАНИЯ

Отчёты создаются в Google Таблице.
Типы: сводка CRM, продажи, финансы, склад, задачи.
Для автоматического отчёта создайте расписание с cron-выражением.
Планировщик должен быть включён: SCHEDULER_ENABLED=true.
Планировщик рассчитан на один экземпляр приложения.

8. РЕЗЕРВНОЕ КОПИРОВАНИЕ

SQLite:
  кнопка в Настройках или Database.backup().
PostgreSQL:
  docker compose exec db pg_dump -U crm crm > backup.sql

Рекомендуется хранить не менее 7 ежедневных копий.

9. ОБНОВЛЕНИЕ

1. Остановите приложение: stop.bat
2. Обновите код из репозитория.
3. Проверьте .env и при необходимости добавьте новые переменные.
4. Запустите start.bat.
5. Проверьте /health и логи logs/app.log.

10. ДИАГНОСТИКА

Healthcheck:
  http://127.0.0.1:8000/health
Логи:
  logs/app.log
Контейнеры:
  docker compose ps
  docker compose logs --tail=100 app

Частые проблемы:
  порт 8000 занят — остановите старый процесс;
  нет доступа к проекту — добавьте пользователя в участники;
  403 Google — проверьте доступ сервисного аккаунта и API;
  OAuth2 — проверьте redirect URI и срок действия токена.
